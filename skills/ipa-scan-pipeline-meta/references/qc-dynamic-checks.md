# iOS 动态检测 QC 16 项质检说明

QC 入口：`qc_dynamic_ios.py --report <细节.html> --risk <风险.html>`，FAIL 即 exit 2。

| # | 检查项 | 判定 |
|---|---|---|
| Q1 | p8 动态实测 tab 存在 | 细节报告含动态 tab |
| Q2 | p3 敏感 API 表含 netlog 实测列 | 静态+动态合并 |
| Q3 | 调用链导图动态节点 | cls_/detail 索引 + 归属 |
| Q4 | p9 xcprivacy 结构 | 必要理由 API/声明/追踪 |
| Q5 | queries 无未标注 scheme | LSApplicationQueriesSchemes 全部有竞对标注 |
| Q6 | 红卡排序 | 问题发现·需整改置前 |
| Q7 | 红卡证据截图 | base64 可解码 |
| Q8 | 状态一致性 | 「动态验证已完成」的卡不得为疑似 |
| Q9 | 分类正确性 | requestAccess 宽泛前缀误配检查（通讯录/相机区分） |
| Q10 | 统计一致 | 报告统计数字 = 卡片实际数 |
| Q11 | 静态实锤卡证据形式说明 | 「📷 证据形式说明」块（编译期字符串非运行时截图） |
| Q12 | 商店条款平台过滤 | iOS 只挂 App Store 5.1.x |
| Q13 | 定级三级制 | 仅动态实锤可标「需整改」 |
| Q14 | HTML 结构闭合 | 报告可解析 |
| Q15 | framework 明细完整性 | 尾部 framework 必须全列（防漏 0 调用点的） |
| Q16 | framework 分析完整性 | Ghidra dump ≥22/23、指纹扫描覆盖 23/23 |

## 定级规则（硬约束）

1. 🔴 **问题发现·需整改**：仅限动态实测证据（埋点/截图/流量三证至少其一），处置直接写整改要求
2. 🔵 **静态实锤·待运行时确认**：编译期确定性证据（二进制字符串/Ghidra 调用点），处置写运行时核实路径
3. 🟡 **疑似·待核实**：静态推断，处置写核实要点

商店条款定级：🔴 拒审级 / 🟠 整改级（逐条标注）。
